# Long-context harness prompt token files

Durable copies of the GLM-5.2 long-context prompt id files (previously only in
volatile /tmp). One token id per line; pass via `GLM52_LONGCTX_TOKENS=<path>`
to `glm52_longctx_golden_test`.

- `glm52_longctx_tokens3.txt` — 2877 ids (tech-doc filler + "Question: What is
  the capital of France?" tail). llama.cpp greedy golden: **12089** (" Paris").
  The first 2000 ids BIND `test-data/glm52-longctx-ckpt.bin` (CMD_SEQ_SNAPSHOT
  @2000) — do not edit this file without regenerating the checkpoint.
- `glm52_needle10k_tokens.txt` — 10,000 ids: tokens3[0:2000] + needle
  ("The secret code is 4917…", code at pos ~2006) + repeated tech-doc filler +
  question tail. Golden: **101474**. Reuses the ckpt@2000. Also the prompt for
  the routing x-ray capture (see `test-data/routing-xray/README.md`).

Ground-truth regeneration: `llama-completion -no-cnv -f <promptfile> -n 1
--temp 0 --top-k 1 -ngl 0 -t 56 --verbose-prompt` on the 436 GB GGUF; parse
ids from the " I <id> -> " verbose lines.

## Perf-test measurement regimes (keeper52 / dsp52)

Both perf tests (`tests/integration/keeper52_test.cpp`,
`tests/integration/dsp52_test.cpp`) support three prompt regimes — see the
MEASUREMENT REGIMES block in each file header, spec/reports/DSP52_BOOST.md,
and TD-PREFILL-NONDET (spec/TECH_DEBT.md):

1. **Bare-seed** (default, canonical keeper number): no fixture needed.
2. **Prompt-fed** — the CANONICAL prompt regime is this directory's
   `glm52_longctx_tokens3.txt` capped to its first **512** ids:
   - keeper52: `KEEPER52_PROMPT=test-data/prompts/glm52_longctx_tokens3.txt
     KEEPER52_PROMPT_TOKENS=512`
   - dsp52:    `DSP52_PROMPT=test-data/prompts/glm52_longctx_tokens3.txt
     DSP52_PROMPT_TOKENS=512`
   Chunked prefill is cross-process non-deterministic (TD-PREFILL-NONDET):
   post-prompt trajectories/hit/walls are per-run lottery samples — compare
   medians of >=2 runs, walls only, never tokens.
3. **Teacher-forced** (`KEEPER52_FORCE_TRAJ` / `DSP52_FORCE_TRAJ` =
   <trajectory file>, one committed token id per line, normally combined
   with the regime-2 prompt): pins the trajectory, making prompt-conditioned
   runs cross-run comparable (walls honest — every step still executes).

Forced-trajectory fixtures (regime 3):

- `dsp52_forced_traj_r1.txt` — 100 ids: the committed continuation of a real
  PLAIN prompt-fed dsp52 run (regime 2, canonical 512-cap prompt, REEF
  recipe, hit-family 0.65; captured for the DSP52_BOOST saga-conclusion
  verdict, commit e5d71ab3). Used as the forced stream of BOTH arms of the
  champion-vs-plain matched-trajectory A/B.
- `keeper52_forced_traj_smoke16.txt` — 16 ids: the committed continuation of
  a keeper52 PROMPT-FED smoke (regime 2, canonical 512-cap prompt, EP=4,
  KEEPER52_TOKENS=16; 2026-08-02). SMOKE-LENGTH ONLY — regenerate a
  100-token file with the recipe below before using it for reportable
  forced-regime measurements.

Regeneration recipe (either test): run a plain prompt-fed pass with the
step dump on and capture the committed stream —

    KEEPER52_PROMPT=test-data/prompts/glm52_longctx_tokens3.txt \
    KEEPER52_PROMPT_TOKENS=512 LS_KEEPER_DUMP_ALL=1 \
      ./build/tests/integration/keeper52_test --gtest_filter='Keeper52Test.*' \
      2>&1 | tee /tmp/run.log
    grep -E '^  step ' /tmp/run.log | sed -E 's/.*token= *([0-9]+).*/\1/' \
      > test-data/prompts/<name>.txt

(dsp52: same with `DSP52_PROMPT`/`DSP52_PROMPT_TOKENS`, `DSP52_SPEC=0` for
the plain loop, and the dsp52 gtest filter. One id per line = the committed
trajectory; a forced run over the same prompt then commits exactly this
stream and reports the model-match rate.)

## Reproducing the matched-trajectory A/B (DSP52_BOOST saga conclusion)

The final verdict table (plain 8.84 med vs champion speculative 7.62 med
wall tok/s — spec/reports/DSP52_BOOST.md "Saga conclusion") is regime 2+3:
canonical 512-cap prompt + the dsp52_forced_traj_r1.txt forced stream, both
arms LS_IPC_PIN=1 + explicit canonical EP combine, canonical REEF recipe,
100 generated tokens (default), 4 idle SM120 GPUs, arena warm. Runs serial;
medians of >=2 runs per arm.

**1. PLAIN arm (as measured — the A/B control):**

    CUDA_DEVICE_ORDER=PCI_BUS_ID CUDA_VISIBLE_DEVICES=0,1,2,3 \
    KEEPER52_REEF_ORCH=1 LS_IPC_PIN=1 \
    LAYERSTORM_DETERMINISTIC_EP_COMBINE=1 \
    LAYERSTORM_DETERMINISTIC_EP_COMBINE_PRECISION=bf16 \
    DSP52_CKPT=/srv/models/dspark/GLM-5.2-speculator.dspark.orig \
    DSP52_SPEC=0 \
    DSP52_PROMPT=test-data/prompts/glm52_longctx_tokens3.txt \
    DSP52_PROMPT_TOKENS=512 \
    DSP52_FORCE_TRAJ=test-data/prompts/dsp52_forced_traj_r1.txt \
      ./build/tests/integration/dsp52_test \
      --gtest_filter='Dsp52Test.SpeculativeHundredTokenDecodeFetchAndRun_FullFit_EP4_GLM52'

keeper52-NATIVE equivalent (same fixtures through the new
KEEPER52_PROMPT/KEEPER52_FORCE_TRAJ knobs; the deterministic-combine pair
defaults ON in both fixtures):

    CUDA_DEVICE_ORDER=PCI_BUS_ID CUDA_VISIBLE_DEVICES=0,1,2,3 \
    KEEPER52_EP=4 KEEPER52_REEF_ORCH=1 LS_IPC_PIN=1 \
    KEEPER52_PROMPT=test-data/prompts/glm52_longctx_tokens3.txt \
    KEEPER52_PROMPT_TOKENS=512 \
    KEEPER52_FORCE_TRAJ=test-data/prompts/dsp52_forced_traj_r1.txt \
      ./build/tests/integration/keeper52_test \
      --gtest_filter='Keeper52Test.HundredTokenDecodeFetchAndRun_FullFit_EP2_GLM52'

NOTE: keeper52 has NO DSpark draft — no draft-GPU VRAM carve on the last
5080 (its expert window stays KEEPER52_EXPERT_CACHE_GB_5080, default 11 GB
vs dsp52's DSP52_DRAFT_CACHE_GB=4) and no draft-vs-experts gpu3 contention
tax — so its walls run HIGHER than the dsp52 plain arm at the same forced
trajectory. It is the no-draft-topology REFERENCE, not the A/B control;
the verdict's plain arm is the dsp52 command above (same binary as the
champion).
